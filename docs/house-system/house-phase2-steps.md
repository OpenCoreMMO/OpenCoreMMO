# House System — Phase 2 Step-by-Step (Map Load + Persistence)

> Companion to `house-phase1-steps.md` and the master plan `House-System-Plan.md`
> ("Phase 2 — Map load + persistence"). Phase 1 (the pure `House` aggregate, value objects,
> `HouseService`, `HouseStore`, `HouseFactory`, the `IHouseRepository` contract, and the unit-test
> suite) is assumed **merged**. Phase 2 makes those classes *live*: it loads houses from the DB,
> attaches them to the world during map load, and persists ownership/access changes. **No Lua, no
> talkactions, no spells** — that is Phase 3.

---

## Important deviations from the master plan (read first)

Grounded in the real code, three master-plan assumptions are **wrong** and the steps below correct them.
Do not "fix" the steps back toward the plan.

1. **The OTBM house-tile parser is already finished.** The plan says to finish the stub
   `OTBM/Structure/TileArea/HouseTile.cs`. In reality `TileNode` already reads the house id:
   `TileNode.cs:29` -> `if (node.Type == NodeType.HouseTile) HouseId = stream.ReadUInt32();`, **before**
   `ParseAttributes`, and surfaces `TileNode.HouseId` (`uint`, default 0) + `TileNode.NodeType`
   (`OTBM/Structure/TileArea/TileNode.cs:38-42`). `NodeType.HouseTile = 14` already exists
   (`OTB/Enums/NodeType.cs:19`). `WorldLoader.LoadTile` already passes `tileNode.HouseId` into
   `_tileFactory.CreateTile(...)` (`WorldLoader.cs:113-115`). The `HouseTile.cs` file is **dead,
   fully-commented scaffolding** and unused. -> **Step 1 is now: delete the dead stub and add a
   regression test that proves the existing parser reads `HouseId` correctly**, not "write a parser".

2. **There is no EF migration system in this repo.** The plan's "EF migration for SQLite + Postgres"
   does not apply. Schema is created at startup via `context.Database.EnsureCreatedAsync()` (after an
   optional `EnsureDeletedAsync()` when `DropOnStartup`) -- see `Program.cs:209-214`. There is **no
   `Migrations/` folder anywhere** and the providers (`UseSQLite`/`UsePostgreSQL`/`UseInMemory`) are
   selected in `DatabaseInjection.cs:59-68`. Entity changes flow straight from the model. -> **Step 6
   is now: change the entities + EF configs and verify the schema is regenerated by `EnsureCreated`
   on all three providers**, not "generate a migration". (If the project later adopts migrations, this
   step is where they would hook in.)

3. **Guilds are NOT bulk-loaded before the world.** The plan's load order "Guilds first -> Houses ->
   World+attach" assumes a startup-time guild load. There is none: `GuildLoader : ICustomLoader` is
   auto-registered for DI but invoked **lazily, per player, at login** (`PlayerLogInCommand.cs:125`
   `guildLoader.LoadAsync(...)`). `IGuildStore` is keyed by `ushort` id and has **no by-name lookup**
   (`IGuildStore.cs`). -> **The access-list loader (Step 5) must resolve guild names via
   `IGuildRepository.GetByName(...)` itself** (it exists: `GuildRepository.cs:28`), and the real boot
   ordering is **HouseLoader -> HouseAccessListLoader -> WorldLoader+attach -> finalize** (Step 7), all
   invoked explicitly from `Program.cs` *before* `WorldLoader.Load()`.

Smaller deviations (handled inline in the steps):

- `IHouseRepository` shipped in Phase 1 with **only `Save(House)`** (`Repositories/IHouseRepository.cs`).
  Phase 2 adds `SaveAccessList(uint houseId, uint listId, string text)` to the Domain interface
  and `GetAll()`/`GetById(uint)` (returning `HouseEntity`) to a **separate Data-layer interface**
  consumed only by loaders -- mirroring the Mail split (keeps Domain EF-free). See Step 4.
- `House.LinkTile` **throws if `tile.CanEnterFunction is not null`** (`House.cs:66`). The WorldLoader
  attach must therefore never link the same tile twice and must run before any other writer touches
  `CanEnterFunction`. (See Risk R7.)
- `House.LinkDoor(uint, IItem)` / `LinkBed(IItem)` take `IItem`, not `IDoorItem`/`IBedItem` -- there are
  no door/bed domain interfaces. Door = `item.Metadata.Attributes.GetAttribute(ItemTypeAttribute.Type)
  == "door"` with door id from `ItemAttribute.DoorId`; bed = `item.Metadata.HasFlag(ItemFlag.Bed)`.
- `HouseAccessList` exposes `AllowEveryone()` (not `AllowAll()`), `AddPlayer/AddGuild/AddGuildRank/Clear`.
- The access-list loader, house loader, and world-attach all live in **Loaders**, which already
  references `NeoServer.Data` (entities) and `NeoServer.Domain` -- so no new project references.
- **DI for `IHouseStore`, `IHouseService`, `IHouseFactory`, `HouseConfiguration`, `IHouseRepository`
  is not registered yet.** `HouseStore`/`HouseService`/`HouseFactory` classes exist from Phase 1 but
  are unreferenced by any IoC module. Phase 2 wires all of them (Step 8) plus the seam impls.
- `HouseConfiguration` is `record HouseConfiguration(bool TransferItemsToDepotOnOwnershipChange = true)`
  in `Common/GameConfiguration.cs:54`; it must be registered as a singleton for `HouseService`.

## Phase 2 goal & definition of done

**Goal:** Boot the server against a house-bearing OTBM and end up with fully-populated `House`
aggregates in `IHouseStore` -- owners and access lists loaded from the DB, every house tile linked
(ProtectionZone set, `CanEnterFunction` installed), doors/beds linked, entry positions resolved -- with
ownership/access mutations persisting through `HouseRepository` on SQLite, Postgres, and InMemory.

**Done when:**
- [ ] Dead `OTBM/Structure/TileArea/HouseTile.cs` stub removed; a loader test asserts `TileNode` reads
      `HouseId` from an `OTBM_HOUSETILE` node without corrupting subsequent tiles.
- [ ] `HouseEntity` columns renamed (`Onwer`->`OwnerGuid`, `Paid`->`PaidUntil`) + `OwnerName`,
      `OwnerAccountId`, `EntryX/Y/Z` added; auction columns untouched; EF config + index updated.
- [ ] `IHouseRepository` extended (Domain `Save`/`SaveAccessList`; Data `GetAll`/`GetById`) and
      `HouseRepository : BaseRepository<HouseEntity>` implements both, mirroring the Mail repository.
- [ ] `HouseLoader` populates `IHouseStore` from `HouseRepository.GetAll()` via `IHouseFactory`.
- [ ] `HouseAccessListLoader` builds `HouseAccessList`s from `HouseListEntity` rows (resolving guild
      names via `IGuildRepository`) and calls `house.SetAccessList(...)`.
- [ ] `WorldLoader` attaches house tiles: `LinkTile`/`LinkDoor`/`LinkBed`, and **skips the static-tile
      cache fast-path when `houseId > 0`** (both in `WorldLoader.LoadTile` and `TileFactory.CreateTile`).
- [ ] `Program.cs` runs **HouseLoader -> HouseAccessListLoader -> WorldLoader.Load -> house finalize**
      in that order; finalize sets each house `EntryPosition` and logs houses with 0 tiles.
- [ ] All house DI registered (`IHouseStore`, `IHouseRepository`, `IHouseFactory`, `IHouseService`,
      `HouseConfiguration`, and the three `HouseService` seams).
- [ ] `dotnet build` clean; loader/persistence tests green; manual boot verification (see Verification)
      passes on SQLite and Postgres.
- [ ] No Lua/talkaction/spell changes (Phase 3).

**References to mirror:** `Loaders/Guilds/GuildLoader.cs` (loader shape + DI via `ICustomLoader`),
`Data/Repositories/GuildRepository.cs` + `Repositories/Player/PlayerMailItemRepository.cs`
(`BaseRepository<T>` + `NewDbContext` + `Include` pattern, and double-interface registration),
`WorldLoader.cs` (tile creation + cache).

## Build order (dependency-first)

Each step lists **What -> Where -> Depends on -> Done-when**. Persistence first (loaders read it), then
loaders, then world attach, then orchestration, then DI.

### Step 1 -- Remove dead OTBM stub + parser regression test
- **What:** Delete the commented-out `HouseTile.cs` stub (unused dead code; the real parse lives in
  `TileNode`). Add a focused test that builds an `OtbNode` of `NodeType.HouseTile` with a known
  `HouseId` followed by a tile-flags attribute + one item, parses via `TileNode`, and asserts
  `HouseId` is correct and `Flag`/`Items` parse intact (proving the uint32 read did not misalign the
  rest of the stream). If a loaders test project does not exist, place it where existing OTB/OTBM
  parsing tests live (grep `OtbParsingStream`/`TileArea` under `tests/`).
- **Where:** delete `src/Loaders/NeoServer.Loaders/OTBM/Structure/TileArea/HouseTile.cs`;
  test under the loaders test project (or a new `tests/NeoServer.Loaders.Tests/OTBM/` if none).
- **Depends on:** nothing.
- **Done-when:** stub gone, `dotnet build` clean, the parse test green. (Retires Risk R1 cheaply.)

### Step 2 -- `HouseEntity` schema changes
- **What:** In `HouseEntity.cs` rename `int Onwer` -> `int OwnerGuid`; rename `int Paid` ->
  `long PaidUntil` (unix seconds, 0 = never paid); add `string OwnerName`, `int OwnerAccountId`, and
  nullable `int? EntryX`, `int? EntryY`, `int? EntryZ`. Keep `Warnings`, `Rent`, `TownId`, `Size`,
  `Beds`, `HouseLists` and all auction columns (`Bid`, `BidEnd`, `LastBid`, `HighestBidder`) untouched
  (out of scope). Columns are snake_cased automatically by `NeoContext` (`OwnerGuid` -> `owner_guid`),
  so no manual column attrs.
- **Where:** `src/Database/NeoServer.Data/Entities/HouseEntity.cs`.
- **Depends on:** nothing.
- **Done-when:** entity compiles; field names match what Step 4/6 read.

### Step 3 -- EF configuration update
- **What:** In `HouseEntityConfiguration.cs` replace `builder.Property(h => h.Paid)` with `PaidUntil`,
  replace `builder.HasIndex(h => h.Onwer)` with `builder.HasIndex(h => h.OwnerGuid)`, keep the `TownId`
  index, and add sensible config for the new columns (`OwnerGuid`/`OwnerAccountId`/`PaidUntil` default
  0; `OwnerName` optional `HasMaxLength(255)`; `EntryX/Y/Z` nullable, no default). In
  `HouseListEntityConfiguration.cs` the composite primary key `(HouseId, ListId)` already provides the
  `(HouseId, ListId)` lookup index the plan asks for -- confirm it is present; only add an extra index
  if a non-PK access pattern is needed (it is not). No `ForSqLite*` variant is required (the House
  configs are applied in both branches of `OnModelCreating`).
- **Where:** `src/Database/NeoServer.Data/Configurations/HouseEntityConfiguration.cs` and
  `HouseListEntityConfiguration.cs`.
- **Depends on:** Step 2.
- **Done-when:** config compiles; no reference to removed `Onwer`/`Paid` remains anywhere in `src/`.

### Step 4 -- Extend `IHouseRepository` + implement `HouseRepository`
- **What:**
  - Two interfaces, like the Mail pattern (where `PlayerMailItemRepository` implements both
    `IPlayerMailItemRepository` (Data) and `IPlayerMailRepository` (Domain)):
    - Domain `Repositories/IHouseRepository.cs` stays EF-free: keep `void Save(House)`, add
      `void SaveAccessList(uint houseId, uint listId, string text)`. Domain types only -- never expose
      `HouseEntity`.
    - New Data `Data/Interfaces/IHouseRepository.cs` (mirror `IGuildRepository`):
      `Task<IEnumerable<HouseEntity>> GetAll();` and `Task<HouseEntity> GetById(uint id);` (returns
      entities; consumed only by the loaders).
  - Implement `HouseRepository : BaseRepository<HouseEntity>` (`Data/Repositories/HouseRepository.cs`)
    implementing both interfaces:
    - `GetAll()` -> `context.Houses.Include(h => h.HouseLists).ToListAsync()`.
    - `GetById(uint)` -> same with `Include` + `FirstOrDefaultAsync(h => h.Id == (int)id)`.
    - `Save(House house)` -> load-or-create `HouseEntity` by `house.Id`, map domain -> entity
      (`OwnerGuid`, `OwnerName`, `OwnerAccountId`, `PaidUntil` = unix from `house.PaidUntil`,
      `Warnings` = `PayRentWarnings`, `Rent`, `TownId`, `EntryX/Y/Z` from `house.EntryPosition`),
      `Update`/`Add`, `SaveChangesAsync`. Map only owned scope -- never touch auction columns.
    - `SaveAccessList(uint houseId, uint listId, string text)` -> upsert the `HouseListEntity`
      `(houseId, listId)` row `List` text (used by Phase 3; ship now so the contract is complete).
  - Mirror `GuildRepository`/`PlayerMailItemRepository` for ctor (`DbContextOptions<NeoContext>,
    ILogger`) and `NewDbContext` usage. The Domain `Save`/`SaveAccessList` are `void` (Phase 1
    `HouseService` calls `Save` synchronously) -- bridge to an async core with
    `.GetAwaiter().GetResult()`, matching the GuildLoader sync-wrapper idiom (`GuildLoader.cs:35-39`).
- **Where:** `src/Core/NeoServer.Domain/Repositories/IHouseRepository.cs`,
  `src/Database/NeoServer.Data/Interfaces/IHouseRepository.cs` (new),
  `src/Database/NeoServer.Data/Repositories/HouseRepository.cs` (new).
- **Depends on:** Steps 2-3.
- **Done-when:** repo compiles; a persistence test (InMemory or SQLite) round-trips a `House` through
  `Save` then `GetById` and gets owner/rent/entry back; Domain project has no new EF reference.

### Step 5 -- `HouseAccessListLoader`
- **What:** `Loaders/Houses/HouseAccessListLoader.cs`. Given a `House` and its `HouseListEntity` rows,
  for each row build a `HouseAccessList` from the `List` text and call
  `house.SetAccessList((uint)row.ListId, list)`. Port the forgottenserver house-list text grammar
  minimally:
  - line `*` -> `list.AllowEveryone()`.
  - guild / guild-rank line (e.g. `@GuildName` or `GuildName, RankName`) -> resolve the guild by name
    via `IGuildRepository.GetByName(name)` (guilds are not in `IGuildStore` at boot -- see Deviation 3);
    if found, `AddGuild(id)` or `AddGuildRank(id, rankLevel)`. Skip + warn if unknown.
  - any other non-empty line -> `list.AddPlayer(name.Trim())`.
  Keep the parser small and unit-tested in isolation (no world dependency). Inject
  `Data.Interfaces.IGuildRepository` + `ILogger`. Implement `ICustomLoader` so DI auto-registers it
  (it is called explicitly from the HouseLoader, not auto-invoked). Cache guild-name lookups per load
  run to avoid N DB queries (Risk R4).
- **Where:** `src/Loaders/NeoServer.Loaders/Houses/HouseAccessListLoader.cs`.
- **Depends on:** Step 4 (entities), Phase 1 `HouseAccessList`/`SetAccessList`.
- **Done-when:** unit tests cover `*` / player / guild / guild-rank / unknown-guild lines; loader compiles.

### Step 6 -- `HouseLoader`
- **What:** `Loaders/Houses/HouseLoader.cs`, mirroring `GuildLoader`. `Load()`:
  1. `await houseRepository.GetAll()` (Data `IHouseRepository`).
  2. for each `HouseEntity`: `houseFactory.Create(id, name, townId, rent, ownerGuid, ownerName,
     ownerAccountId, paidUntil(from unix), warnings)`.
  3. set `house.EntryPosition` from `EntryX/Y/Z` if all present (else null -> resolved at finalize).
  4. `houseStore.AddOrUpdate(house.Id, house)`.
  5. call `houseAccessListLoader` per house with that entity `HouseLists`.
  6. log house count.
  Expose a plain `Load()` invoked explicitly from `Program.cs` (ordering must be deterministic relative
  to `WorldLoader`; do not rely on `IStartupLoader` bulk-iteration, which runs at `Program.cs:103`,
  after `WorldLoader.Load()`). Register as a singleton in `LoaderInjection` (Step 8).
- **Where:** `src/Loaders/NeoServer.Loaders/Houses/HouseLoader.cs`.
- **Depends on:** Steps 4-5, Phase 1 `IHouseFactory`/`IHouseStore`.
- **Done-when:** with a seeded DB, `HouseLoader.Load()` fills `IHouseStore` with owned houses + access
  lists (no tiles yet). Verified by a test using the InMemory provider + `HouseStore`.

### Step 7 -- `WorldLoader` attach (LinkTile/LinkDoor/LinkBed) + cache-skip
- **What:**
  - Add `IHouseStore houseStore` to the `WorldLoader` ctor (and its registration -- Step 8).
  - In `LoadTile`, before the static-cache fast-path (`:96-109`), guard on `tileNode.HouseId`: if `== 0`
    keep the existing cache path; if `> 0` skip the cache entirely and always build a fresh tile (house
    tiles must never be served from the shared static cache -- Risk R2). Pass `useCache: false` into
    `CreateTile` for house tiles.
  - After the tile is created and added to the world, when `tileNode.HouseId > 0`:
    - `var house = houseStore.GetByHouseId(tileNode.HouseId);` -- if null, `logger.Warning` (orphan
      house tile: references a house id with no DB row) and continue.
    - `if (tile is IDynamicTile dyn) house.LinkTile(dyn);` (house tiles are always dynamic because
      `TileFactory` forces dynamic for `houseId > 0`; log if it ever is not). Wrap in try/catch so one
      double-linked/bad tile (LinkTile throws) does not abort world load (Risk R7).
    - scan `dyn.AllItems`: if an item is a door
      (`item.Metadata.Attributes.GetAttribute(ItemTypeAttribute.Type) == "door"`) read its door id from
      `ItemAttribute.DoorId` and `house.LinkDoor(doorId, item)`; if it is a bed
      (`item.Metadata.HasFlag(ItemFlag.Bed)`) `house.LinkBed(item)`.
  - Also harden `TileFactory.CreateTile`: the cache lookup (`:21-25`) runs before `isHouseTile` is
    computed (`:27`), so a `houseId > 0` tile could otherwise resolve to a cached `StaticTile` (which
    drops `HouseId`). Early-compute `isHouseTile` and force `useCache = false` when it is true inside
    `CreateTile`, so the guard holds regardless of caller (defensive; the loader already passes
    `useCache:false`).
- **Where:** `src/Loaders/NeoServer.Loaders/World/WorldLoader.cs`,
  `src/Core/NeoServer.Domain/World/Factories/TileFactory.cs`.
- **Depends on:** Step 6 (houses in store before tiles attach), Phase 1 `LinkTile/LinkDoor/LinkBed`.
- **Done-when:** booting with a house OTBM links the expected number of tiles per house; house tiles
  have `ProtectionZone` set and a non-null `CanEnterFunction`; no house tile is a cached `StaticTile`;
  doors/beds linked.

### Step 8 -- DI registration (all house wiring + seam impls)
- **What:**
  - `DataStoreInjection.cs` -> `builder.AddSingleton<IHouseStore, HouseStore>();` (next to `IGuildStore`).
  - `DatabaseInjection.cs` -> register the one `HouseRepository` class against both interfaces (mirror Mail at `DatabaseInjection.cs:34,39`): `AddSingleton<NeoServer.Data.Interfaces.IHouseRepository, HouseRepository>();` and `AddSingleton<NeoServer.Domain.Repositories.IHouseRepository, HouseRepository>();` (or register the concrete once and forward both interfaces to that instance).
  - `FactoryInjection.cs` -> `AddSingleton<IHouseFactory, HouseFactory>();`.
  - `ServiceInjection.cs` -> `AddSingleton<IHouseService, HouseService>();` and the three seams -- ship concrete impls now (Phase 1 only mocked them):
    - `IHouseEviction.TeleportToExit` -> reuse the existing teleport/movement path (grep `IToMapMovementService` / `MapTool`) so eviction actually moves players.
    - `IHouseBedWaker.WakeAll` -> minimal impl (no-op + log acceptable for Phase 2 if bed-wake UI is Phase 3; do not block on it).
    - `IHouseDepotTransfer.TransferToOwnerDepot` -> use `IPlayerDepotItemRepository` for offline owners (Risk R3); the call is already guarded by `HouseConfiguration.TransferItemsToDepotOnOwnershipChange` inside `HouseService`.
  - Register `HouseConfiguration` singleton (`new HouseConfiguration()`), alongside the other config records (`ConfigurationInjection`/`ServiceInjection`).
  - `LoaderInjection.cs` -> `AddSingleton<HouseLoader>();` and `AddSingleton<HouseAccessListLoader>();` (the access-list loader also matches `ICustomLoader`; an explicit singleton keeps `Program.cs` resolution simple).
- **Where:** the five IoC modules above + the seam impl files (server/services layer).
- **Depends on:** Steps 4-7.
- **Done-when:** container builds with no missing-dependency errors; `HouseService` and `WorldLoader` resolve. (A `TestSetup` DI smoke test resolving `WorldLoader` + `IHouseService` is ideal.)

### Step 9 -- Boot orchestration + finalize in `Program.cs`
- **What:** In `Program.cs`, before `container.Resolve<WorldLoader>().Load(...)` (`:100`), add `container.Resolve<HouseLoader>().Load();` (houses + access lists into `IHouseStore`). After `WorldLoader.Load(...)` returns, add a finalize pass (method on `HouseLoader` or a small `HouseFinalizer`): for each house in `IHouseStore`, if `EntryPosition` is still null set it to the first linked tile location (or the entity `EntryX/Y/Z`), and `logger.Warning` for any house with `TileCount == 0` (orphaned DB house with no map tiles). Keep it in the existing `logger.Step(...)` style. Do not move to `IStartupLoader` (that batch runs at `:103` with non-deterministic order; explicit calls match how `WorldLoader`/`SpawnLoader` are invoked).
- **Where:** `src/Standalone/Program.cs` (around `:96-103`).
- **Depends on:** Steps 6-8.
- **Done-when:** boot logs "N houses loaded" then world tiles then finalize; entry positions set; zero-tile houses warned.

## Risks specific to Phase 2

1. **R1 -- OTBM stream alignment (was "highest risk", now retired by Step 1).** The plan feared a mis-aligned uint32 read corrupting the rest of the tile area. The read is already implemented and in the correct order (`TileNode.cs:29`, house id before attributes, escape-aware `ReadUInt32`). The only action is the Step 1 regression test, plus verifying against a real house-bearing OTBM during boot (not just synthetic nodes).
2. **R2 -- Static-tile cache must be bypassed for `houseId > 0` in BOTH `WorldLoader` and `TileFactory`.** `WorldLoader.LoadTile` has an early cache fast-path (`:96-109`) that returns a cached tile before `CreateTile` is called; and `TileFactory.CreateTile` checks its own cache (`:21-25`) before computing `isHouseTile` (`:27`). A house tile served from cache is a `StaticTile` with no `HouseId`, breaking `GetByTile`/`LinkTile` and the protection-zone closure. Both guards are required (Step 7).
3. **R3 -- Offline-owner depot transfer needs depot-store access, not online inventory.** On ownership change/eviction, `HouseService` transfers pickupables to the old owner depot. The old owner is usually offline -> must go through `IPlayerDepotItemRepository`, keyed by account/town, not a live `IPlayer`. The `IHouseDepotTransfer` impl (Step 8) carries this; it stays behind `HouseConfiguration.TransferItemsToDepotOnOwnershipChange`. A naive online-only impl silently drops items.
4. **R4 -- Guild resolution at boot.** Guilds are not bulk-loaded before houses (Deviation 3). The access-list loader must resolve guild names via `IGuildRepository.GetByName` (DB hit) -- cache results per load to avoid N queries, and warn-and-skip unknown guilds rather than throwing.
5. **R5 -- Load ordering.** `HouseLoader` MUST run before `WorldLoader.Load()` (houses must exist in the store when tiles attach), and finalize MUST run after (entry-from-first-tile needs linked tiles). This is explicit-call ordering in `Program.cs` (Step 9), not `IStartupLoader` batch order.
6. **R6 -- Schema regeneration, not migration (Deviation 2).** Renaming `Onwer`/`Paid` changes the generated schema. With `EnsureCreated`, an existing SQLite/Postgres DB will NOT be altered -- the new columns appear only on a fresh DB (or after `DropOnStartup`/manual drop). Document for ops: deployments with persistent house data need a manual ALTER/recreate. InMemory and CI (fresh DB each run) are unaffected. If the project adopts EF migrations later, this is the seam.
7. **R7 -- `LinkTile` double-link throw.** `House.LinkTile` throws if `CanEnterFunction` is non-null (`House.cs:66`). The attach loop must link each tile exactly once and run before any other code sets `CanEnterFunction`. A tile referenced by two house ids (bad map data) will throw -- catch+log per tile in the loader so one bad tile does not abort world load.
